# Bounded catalogue research plan and status

Prepared 16 September 2026. **Initial source check completed; representative joins not executed.** The [current Pro specification recheck](investigation-log.md) found no new route for quest definitions or a complete Battle Pass reward catalogue. The [personal profile investigation](epic-profile-readonly-results.md) established quest progress/template IDs and Season 42 claimed offer IDs, but not readable targets or a complete reward denominator. See the [bounded catalogue-source results](catalogue-source-results.md).

The user authorized this bounded expansion beyond api-fortnite.com Pro. It remains read-only and does not build the Home Assistant integration, card, database or service. Direct authenticated Epic operations remain limited to `athena` and `common_core` `QueryProfile`.

1. Check official Epic public documentation and public game-asset/catalogue surfaces for versioned English quest and Season 42 pass definitions. Do not send personal tokens to catalogue services. Record the exact documented source, version, locale, status and safe response shape.
2. If no suitable first-party read-only surface exists, inspect the single game-asset exporter already identified as an **unverified lead** in the handoff. Verify current documentation, access terms and response shape before any call. Use no paid subscription or bulk export. Limit initial calls to two small read-only requests for a known version/path; stop on auth, unexpected size or ambiguous provenance.
3. Test joins for three deliberately different personal quest instances (a verified BR weekly, an event/cosmetic quest, and a staged quest if present) and three Season 42 offer IDs (free, premium and a multi-grant offer if present). Keep personal identifiers and the claim ledger in memory. A successful quest join must establish stable template/objective IDs, English title, target, reward, visibility and expiry where applicable. A successful pass join must establish page/order, offer/grants, free/premium access, release time and level/quest prerequisites or explicitly mark each missing rule.
4. Save only sanitized, bounded evidence and update the capability matrix and investigation log. If the representative joins fail, record the precise missing fields and stop; do not infer quest targets, pass totals or “all available claimed” from progress alone.

No calls to friend/social, purchasing, account-changing or cosmetic-action endpoints were made. One alternative exporter was considered because the specific Pro catalogue and quest capabilities had already been observed broken or missing. The two initial and two separately authorized follow-up unauthenticated exporter GETs returned HTTP 200. The follow-up established candidate version strings and that `jsonOutput` is an array, but no definition catalogue or quest/pass join. Both two-call bounds are exhausted; step 3's join validation remains unverified.
