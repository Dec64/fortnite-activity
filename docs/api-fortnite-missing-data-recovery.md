## Authentication causal chain

The local request in `tools/probe-api-fortnite.ps1` builds a three-property JSON body and sets UTF-8 `application/json`. The provider SDK sends the same body to `/api/v1/oauth/refresh-device`, and its transport uses `https://prod.api-fortnite.com/api` with `x-api-key`. The old credential set returned HTTP 400. The first sanitizer retained the outer status but discarded the discriminating error subtree. Therefore request-shape drift was not supported by the evidence, while the actual server-side rejection category remains unconfirmed.

The second approved response-safe diagnostic completed at 2026-09-15T18:24:49.5263202Z:

1. It returned outer HTTP 400 and an embedded HTTP 400 signal.
2. No access token, refresh token, returned identity, or changed device credentials was present.
3. The error did not match the safe allowlist for invalid credentials, invalid/mismatched client, invalid grant, missing device auth, request validation, upstream 401/403, or provider 5xx.
4. The identity gate closed, so profile/level, quests, BR inventory and entitlement remained at zero calls.
5. No further call with the stale credential set was made. After interactive OAuth rotated it, exact-identity device refresh succeeded and powered later bounded GET batches.

The corrected private batch completed. Interactive OAuth, rotated device auth, level and BR inventory work; quests and entitlement reproduce the handoff's 401/404 under a token proven valid on adjacent routes. No more calls to these disputed endpoints are justified without changed provider behavior or documentation. Battle Pass remains exhausted at two calls. The provider-submission path has been removed at the user's direction; these results remain local scope evidence.
