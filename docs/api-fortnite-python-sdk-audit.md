# api-fortnite.com Python SDK audit

Inspected 16 September 2026. This is source review plus bounded calls to the **same paid Pro api-fortnite.com service**, not an SDK installation or a switch of providers. No Home Assistant code was built. The audited package is [`fortnite-api-sdk` 0.1.1](https://pypi.org/project/fortnite-api-sdk/), imported as `fortnite_api`; it is distinct from the similarly named package for fortnite-api.com. The [source repository](https://github.com/Tettu0530/fortnite-api-sdk) and its [bundled OpenAPI](https://github.com/Tettu0530/fortnite-api-sdk/blob/main/openapi/swagger.json) are the primary SDK sources.

## Coverage compared with the current provider specification

| Source | Paths | Operations |
| --- | ---: | ---: |
| SDK repository's bundled Swagger | 109 | 110 |
| [Current saved api-fortnite.com specification](../evidence/sanitized/specifications/api-fortnite-openapi.json) | 138 | 140 |

Thirty current paths are absent from the SDK's bundled specification, including `/api/v2/battlepass`, all versioned sprite routes, current player-session and recent-match routes, and window-specific tournament scoring. The SDK's resource source has no sprite resource. Its one route absent from the current specification is [`GET /api/v1/events/tracker/debug`](https://github.com/Tettu0530/fortnite-api-sdk/blob/main/src/fortnite_api/resources/tournaments.py), documented in source as admin debug returning raw Epic `/download` data. It is not a suitable undocumented private-data fallback and was **not called**. A static scan of 99 distinct standard resource requests found no other SDK-only route; binary/multipart helper methods were outside that scan. The SDK therefore does not expose a hidden working quest, locker, Battle Pass or presence API.

The SDK's [`quests.get`](https://github.com/Tettu0530/fortnite-api-sdk/blob/main/src/fortnite_api/resources/quests.py), [`fn.get_entitlement` and `fn.get_br_inventory`](https://github.com/Tettu0530/fortnite-api-sdk/blob/main/src/fortnite_api/resources/fn.py), and [Friends methods](https://github.com/Tettu0530/fortnite-api-sdk/blob/main/src/fortnite_api/resources/friends.py) call the same routes and accept the same `x-fortnite-token` as the investigation's direct requests. Switching transport libraries will not by itself resolve the observed quest 401, entitlement 404, V-Bucks-only inventory or Friends 403. The [`crew` methods](https://github.com/Tettu0530/fortnite-api-sdk/blob/main/src/fortnite_api/resources/crew.py) still return public packs, not personal membership. Notably, [`battlepass.get`](https://github.com/Tettu0530/fortnite-api-sdk/blob/main/src/fortnite_api/resources/battlepass.py) calls `/api/v1/shop/battlepass`, the route whose observed result was news/MOTD-shaped; it does **not** call the newer `/api/v2/battlepass` catalogue route. Its method name is not evidence of a working reward catalogue.

The [transport](https://github.com/Tettu0530/fortnite-api-sdk/blob/main/src/fortnite_api/_transport.py) unwraps successful `data`/`results` envelopes. That explains the earlier local sprite-summary failure and is a useful parsing convention; the current bounded sanitizer now does the same. The transport can also expose raw response/error bodies to callers, so it is not a substitute for the investigation's secret-safe projections. The package declares Python `>=3.10` and classifiers through 3.13; compatibility with the reported Home Assistant Python 3.14 remains unverified. No package was installed.

The [SDK playlist resource](https://github.com/Tettu0530/fortnite-api-sdk/blob/main/src/fortnite_api/resources/playlists.py) and [tournament resource](https://github.com/Tettu0530/fortnite-api-sdk/blob/main/src/fortnite_api/resources/tournaments.py) supplied useful method names and semantics, but the current OpenAPI is the more complete contract. The next provider-only checks need changed documentation/service behavior or a verified mapping source, rather than installing the older SDK and repeating the same failed operations.
